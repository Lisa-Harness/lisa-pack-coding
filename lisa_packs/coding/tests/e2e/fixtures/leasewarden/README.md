# Leasewarden

Leasewarden is a small control plane for a home-lab dnsmasq installation.
It reads the lease file, shows which devices have used an address, and writes
persistent IPv4 reservations into a `dhcp-hostsdir` directory. The HTTP server
and terminal client share one binary. Neither needs a database or a cloud
service; all imports are from Go's standard library or this module.

## Build and check

Use Go 1.23 or later:

```sh
go test ./...
go vet ./...
gofmt -l .
go build -o dist/leasewarden .
```

The module has no external dependencies and no `go.sum`. Building does not
require a compiler for C, containers, dnsmasq, or network access.

## Run on a lab host

Configure dnsmasq with a directory dedicated to this service:

```text
dhcp-hostsdir=/etc/dnsmasq.hosts.d
```

Give the service account read access to the lease file and write access to
that directory. Set a token outside shell history, for example through a
service-manager environment file. The token is fixed for the process lifetime.

```sh
export LEASEWARDEN_TOKEN='replace-with-a-private-value'
./dist/leasewarden server \
  --leases /var/lib/misc/dnsmasq.leases \
  --hostdir /etc/dnsmasq.hosts.d \
  --subnet 192.168.1.0/24 \
  --listen 127.0.0.1:8068
```

There is no fork or privilege-dropping mode. Run in the foreground under your
service manager. `--pid-file` optionally claims an exclusive PID file and
removes it during normal shutdown. A stale file is an operator decision:
verify that its process has stopped before removing it.

By default writes rely on dnsmasq's directory monitoring. Where needed, add
`--dnsmasq-pid /run/dnsmasq.pid` to send SIGHUP after each successful mutation.
Never point this flag at Leasewarden's own PID file. Publish failure returns
503 after the file has been stored; inspect the reservation before retrying.

## HTTP endpoints

All routes except health require `Authorization: Bearer <token>`.
There is no token-issuance endpoint. Keep the bind address on loopback or behind
a trusted reverse proxy; the built-in server does not terminate TLS.

| Method | Route | Request | Success |
| --- | --- | --- | --- |
| GET | `/health` | none | 200, `{"status":"ok"}` |
| GET | `/leases` | none | 200, array of lease records |
| GET | `/clients` | none | 200, summaries grouped by MAC |
| GET | `/addresses/{mac}` | none | 200, matching lease records |
| GET | `/devices/{ip}` | none | 200, matching lease records |
| GET | `/reservations` | none | 200, array of reservations |
| GET | `/reservations/{mac}` | none | 200, one reservation |
| POST | `/reservations` | MAC, IP, optional hostname | 201, stored reservation |
| PUT | `/reservations/{mac}` | IP, optional hostname | 200, stored reservation |
| DELETE | `/reservations/{mac}` | none | 204, no body |

Create example:

```sh
curl -H "Authorization: Bearer $LEASEWARDEN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"mac":"AA-BB-CC-DD-EE-01","ip":"192.168.1.10","hostname":"nas"}' \
  http://127.0.0.1:8068/reservations
```

Responses use `mac`, `ip`, and `hostname`; empty hostname remains an empty
string. MACs normalize to lowercase colon-separated form. IPs must be usable
IPv4 addresses within the configured subnet. Hostnames are lowercase DNS
labels, not fully qualified names. `*` and blank mean no hostname.

Errors generated by handlers are JSON objects with an `error` field:

| Status | Code | Meaning |
| --- | --- | --- |
| 400 | `bad_request` | invalid JSON, non-object body, unknown fields |
| 400 | `invalid` | malformed or missing input, or off-subnet address |
| 401 | `unauthorized` | absent or invalid bearer token |
| 404 | `not_found` | unknown device or reservation |
| 409 | `already_reserved` | POST for an already reserved MAC |
| 413 | `too_large` | body exceeds 16 KiB |
| 422 | `invalid` | PUT omitted its required IP |
| 500 | `storage_unavailable` | host directory could not be read or written |
| 503 | `leases_unavailable` | lease snapshot could not be read |
| 503 | `publish_failed` | durable change could not be reloaded |

Unknown routes and unsupported methods use ServeMux's standard 404/405
responses. A PUT replaces the entire record; omitted hostname is cleared.

## Files and snapshots

A lease line is `<expiry> <mac> <ip> <hostname> <client-id>`.
Zero expiry is infinite. Query endpoints include expired records for diagnosis.
Malformed lines are skipped, off-subnet records are filtered, and every request
opens a fresh snapshot. A missing file is empty at query time, but startup
requires an existing readable regular lease file.

Reservation filenames are `aa-bb-cc-dd-ee-01.conf`; their contents are bare
`aa:bb:cc:dd:ee:01,192.168.1.10,nas` lines ending with a newline. This is the
`dhcp-hostsdir` format, not `dhcp-host=` configuration syntax. Writes stage a
file in the same directory and rename it into place. Managed records are
strictly parsed; unrelated filenames are ignored. Do not run multiple writer
processes against one directory.
